プレーンテキストの中に数式を書きたい、という場面は意外と多い。設計メモ、
コードコメント、チャット、README。選択肢はだいたい2つで、どちらも
帯に短し襷に長しだった。

- **LaTeX をそのまま書く** — `\frac{-b\pm\sqrt{b^2-4ac}}{2a}`。機械可読
  だが、人間には読めない。数式が3行を超えると誰も読まなくなる。
- **アスキーアートで描く** — 読めるが、書くのも直すのも苦行。そして
  機械には読めないので、あとで LaTeX が必要になったら手で書き直し。

数式をアスキーアート化してくれるツール(CAS の pretty printer や
Unicode 数式ジェネレータ)は昔からある。ただしどれも**一方通行**だ。
出力はただの絵で、編集するには元のソースに戻ってやり直すしかないし、
その絵を他のツールに食わせることもできない。

[mascii](https://github.com/ho-oto/mascii) はここを逆転させる。
**絵そのものをソースコードにする**。

```
          ┌────────
     -𝑏 ± √𝑏² - 4𝑎𝑐
𝑥 = ────────────────
            2𝑎
```

これはスクリーンショットではなく、ただのテキストだ。このまま
`mascii aa2tex` に流すとコンパイル可能な LaTeX が出てくるし、エディタで
開けば構造を保ったまま編集を続けられる。

```sh
$ echo '...' | mascii aa2tex
x=\frac{-b\pm \sqrt{b^{2}-4ac}}{2a}
```

## 「AA が一意にパースできる」とはどういうことか

mascii の AA 形式(正準AA)には往復の契約がある:

> どんな数式 AST `x` についても `parse(render(x)) == x`
> (正規化を除いて成立。テストで常時検証)

つまり数式は**常に絵であり、同時に構文木でもある**。エディタは
1キー打つごとに自分の出力を再パースしてこの契約を検査していて、
破れたらバグレポートを自動生成する。形式の健全性が開発ループに
組み込まれている。

ソースコードの比喩で言えば、正準AAは「フォーマッタを通したコード」に
あたる。手書きの入力はもっとルーズでよくて(`x+1` や `E=m c²` のような
ASCII 直書きも受理される)、`mascii fmt` が正準形に整える。文法・正準
スタイル・フォーマッタ、という三点セットで「あとから誰でも編集できる」
を成立させている。

## パース可能にするためのアイデアの核

自由なアスキーアートは本質的に曖昧だ。`a` の下に `b` があるとき、それが
分数なのか、極限なのか、たまたま縦に並んだだけなのか、絵だけからは
決められない。mascii はパーサから逆算して形式を設計している。

**1. すべての部分式は「矩形+基線行」を持つ**

兄弟要素は互いに素な列範囲に横に並ぶ。縦の構造は必ず矩形の内部にしか
存在しない。パースは「基線行を見つけ、左から右に走査し、構造グリフが
主張する矩形に再帰する」だけになる。

**2. 構造は「原子になれない予約グリフ」で描く**

分数罫線 `─`、演算子バンド `┈`、括弧の縦列 `⎛ ⎜ ⎝`、根号 `√` と
そのオーバーライン。これらの文字は通常の内容(原子)としては禁止されて
いるので、絵の中に現れたら必ず構造の主張であり、偶然ではありえない。
逆に原子は許可リスト制で、全文字が幅1セル。全角文字や結合文字が紛れて
グリッドが崩れる事故も入口で弾く。

**3. 範囲は「またがせて」示す。空白を数えない**

分数罫線は分子・分母より必ず広い。`∑` のバンド `┈┈∑┈┈` は極限の幅を
覆う。波括弧の頂点 `⎨` は基線行に乗る。「空白が何個あるか」に依存する
規則はひとつも存在しない — 空白は兄弟の区切りでしかない。これが
手編集に耐える(1文字ズレて壊れない)理由でもある。

**4. 1つの木に1つの綴り**

レンダラの出力が正準形で、パーサはその上位集合を受理し、`fmt` が閉じる。
絵に描き分けられない構造は AST 側でも表現しない、という原則も面白い
ところで、たとえばアクセントの重ね掛けは平坦なリストになっている
(`\hat{\underline{x}}` と `\underline{\hat{x}}` は絵が同じなので、
区別しない)。

## 実例

ラウンドトリップのテストコーパスから(すべて `parse(render(x)) == x` を
検証済み。[対照表](https://github.com/ho-oto/mascii/blob/master/docs/examples.md))。

ガウス積分:

```
 ∞    -𝑥²   ┌─
┈∫┈┈ 𝑒   𝑑𝑥=√π
 -∞
```

```latex
\int_{-\infty }^{\infty }e^{-x^{2}}dx=\sqrt{\pi }
```

コーシー・シュワルツ:

```
⎛  𝑛     _ ⎞  ⎛  𝑛      ⎞⎛  𝑛      ⎞
⎜┈┈∑┈┈ 𝑢ₖ𝑣ₖ⎟²≤⎜┈┈∑┈┈ 𝑢ₖ²⎟⎜┈┈∑┈┈ 𝑣ₖ²⎟
⎝ 𝑘=1      ⎠  ⎝ 𝑘=1     ⎠⎝ 𝑘=1     ⎠
```

行列は格子マーカー `┼` 入りのグリッドなので、空セルがあっても行と列が
曖昧にならない:

```
⎡ cos θ   -sin θ ⎤
⎢        ┼       ⎥
⎣ sin θ   cos θ  ⎦
```

## エディタ: LyX 風の構造編集

`mascii` を起動すると TUI の構造エディタが開く。編集対象はあくまで
AST で、絵はそれに追従する。

- 英字はそのまま数学イタリック、`//` で分数、`^` `_` でスクリプト、
  `(` `[` `{` は自動サイズ括弧。`\` でコマンドミニバッファ
  (`\frac` `\sum` `\alpha` `\bbR` …。`\leq` や `\->`、`\oo` のような
  別綴り・ASCII 綴りも通る)
- 矢印キーは構造の**中を通り抜けて**移動する。`↑`/`↓` で分子⇄分母や
  極限に入り、裸の `∑` や `lim` はバンドに昇格する
- `Shift+←/→` で選択して `\frac` や `\sqrt`、括弧で包む。EasyMotion 風
  ジャンプ(`^G`)、自由カーソル(`^F`)、ブロック選択(`^B`)、
  行列のグリッド編集、undo/redo、マウス対応
- **毎編集後にラウンドトリップを自動検査**。契約が破れる編集を見つけたら
  その場でレポートを吐く

同じエディタコアが WebAssembly にもコンパイルされ、VS Code / Obsidian /
Zed の統合プロトタイプがある。ブラウザでも同じキーバインドで動く。

## AI エージェントとの相性

形式が「厳密な文法を持つプレーンテキスト」なので、LLM が直接読み書き
できる。リポジトリの `SKILL.md` は AI エージェント向けの自己完結した
形式ガイドで、`mascii fmt` で検証し `aa2tex` で意味を確認する、という
検証ループまで含む。人間とエージェントが同じ Markdown を保守する時代に、
「双方が読めて、双方が編集できて、機械変換もできる」数式表現は
ちょうどよい落とし所だと思っている。

## 使ってみる

```sh
git clone https://github.com/ho-oto/mascii
cd mascii
cargo run              # TUI エディタ(^Y で AA をクリップボードへ)
cargo run -- aa2tex    # 標準入力の AA を LaTeX に
cargo run -- tex2aa    # LaTeX を AA に(best-effort。KaTeX/MathJax 方言)
cargo run -- fmt       # 手書き AA を正準形に整形
```

<!-- crates.io 公開後は `cargo install mascii` に差し替え -->

まだ若いプロジェクトで、AA 形式自体も進化する可能性がある。LaTeX は
双方向(自前出力は完全往復、外部 LaTeX は best-effort 読み込み。エディタ
内でも `\tex` でペースト可)。MathML 出力はロードマップにある。
形式の仕様は
[docs/aa-spec.md](https://github.com/ho-oto/mascii/blob/master/docs/aa-spec.md)、
設計の経緯は
[docs/design.md](https://github.com/ho-oto/mascii/blob/master/docs/design.md)
にまとまっている。
