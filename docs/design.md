# mascii 設計文書

## ビジョン

プレーンテキストの世界で数式を第一級に扱う。人間が読める 2D アスキーアート
(Unicode 数式記号優先)と数式 AST が**決定論的に相互変換**できれば:

- AA のまま考え、機械的に LaTeX / Typst / MathML に変換できる
- 「AA は後から編集しづらい」という問題は CLI ツール(parse → 構造編集 →
  re-render)を挟むだけで解消する
- TUI エディタ(LyX 風)は AST を直接編集する快適なフロントエンドになる

このため内部表現は TeX 文字列ではなく **AST**(`src/ast.rs`)であり、
2D レンダリング・LaTeX/Typst 出力・構造編集のすべてを AST から導出する。

## アーキテクチャ

```
                    ┌────────────┐
   TUI editor ────▶ │            │ ──▶ render.rs ──▶ 正準AA (canonical)
  (editor.rs)       │    AST     │ ◀── parse.rs  ◀── AA テキスト
                    │  (ast.rs)  │ ──▶ latex.rs  ──▶ LaTeX
                    │            │ ──▶ typst.rs  ──▶ Typst
                    └────────────┘
   symbols.rs / symbols_ext.rs: コマンド名 ⇄ Unicode(4000+ 記号)
```

- `render.rs` と `parse.rs` は正準AA仕様(docs/aa-spec.md)の表と裏。
  **必ず同時に変更し、`tests/roundtrip.rs` を通すこと。**
- カーソル = 「入れ子 Row へのパス + 列」(LyX と同じモデル)。
- 正しさの根拠はラウンドトリップ性:
  `parse(render(normalize(x))) == normalize(x)`(実式コーパス + ランダム生成
  2000 ケースのプロパティテストで検証)。

## 主要な設計判断と経緯

1. **AST を最初から内部表現にする**(TeX 文字列を持たない)
   — 構造編集にはどのみち AST が必要で、AA⇄AST 一対一対応という最終目標への
   一本道のため。

2. **Unicode 積極使用** — `x²` `aᵢ` などのインライン上付き・下付き、数学
   イタリック体(`𝑥`)、`−` `⋅` などは**別コードポイント**なので、見た目が
   良くなるだけでなく曖昧性を根本から消す(tex2utf 系の純ASCII AA より
   パースが簡単になる)。

3. **上下極限のバンド記法 `┄┄∑┄┄`** — 無標識の上下極限は原理的に非可逆:
   `∑_{n=1}^{∫}` と `∫_{∑_{n=1}}` が同一の絵になる反例を実レンダラで確認した
   (`examples/ambig.rs` に保存)。ユーザー提案の「範囲標識 `~~~X~~~`」を
   基線上のバンドとして洗練し、分数罫線と同じ「範囲+基線」の二役を持たせた。
   極限が両方空なら裸の `∫` のまま(バンドなし)。

4. **compact(詰め)組版 → 全面撤去(2026-07)** — 当初は display モードで
   二項演算子の前後に空白1を自動挿入し、スクリプト引数・極限・行列セルのみ
   詰め組み(scriptstyle 相当)としていた。整形 Spacer(§21)で手動の間隔
   調整が可能になったため、ユーザー判断で自動演算子空白ごと廃止。
   二層組版の区別が消えて仕様・実装とも単純化し、LaTeX/Typst 出力の組版は
   元々ツール側の仕事なので失うものがない。

5. **`⬚` 明示基底** — 行頭のスクリプト(`[Sup(x)]`)は `⬚ˣ` と描画。
   空行 `[]` との衝突を防ぐ。空の必須スロットも `⬚`。

6. **アクセントは 2D マーク**(Unicode 結合文字は不採用 — グリッドの列モデル
   を壊すため)。基底の真上/真下のセルは他の何にも使われない空き地なので
   1 セル検査でパースできる。マーク文字は原子と互いに素な予約集合
   (`~`→`˜`, `→`→`⇀` など)とし、上マークと下マークも互いに素にすることで
   「左端列に2文字が縦に並んだときの基線」も一意に決まる(ユーザー指摘)。

7. **行列は `⎡⎤` + 空白帯区切り** — `( )` との区別のため丸括弧行列は
   採用しない(`(x)` の 1×1 行列と括弧の衝突)。列区切り空白2列・行区切り
   空白1行。入れ子行列はブラケット保護(いずれかの行でブラケット対の内側に
   ある列は区切りにしない)で守る。

8. **sin/cos は立体、変数はイタリック** — 描画時イタリック化のおかげで
   立体英字列=関数名が無曖昧。正準形式はイタリック固定(Ctrl+T は表示専用)。

9. **無条件マージン廃止 → バー接触時のみスペーサ** — 当初 Frac/BigOp に
   常時1列マージンを付けたが、スクリプト引数内部に「全高空白列」を作り、
   外側から見た分割を壊すことがプロパティテストで判明。空白列は「同一基線の
   兄弟の区切り」しか意味しないよう、`──`/`┄┄` が接触する場合のみ空白1列を
   挿入する規則に変更(分割されても normalize の合流で正しく復元される)。

10. **normalize(正規形)** — `Sup(a);Sup(b)` と `Sup(a++b)` は同じ絵になる
    ため、隣接同種スクリプトを合流した形を正規形とし、パーサは正規形のみを
    返す。合流が新たな隣接を生むため合流後に再正規化(冪等性が必要 —
    プロパティテストで発見したバグ)。

11. **記号カバレッジ** — ユーザー製 VSCode 拡張
    [ho-oto/mathematical-symbols](https://github.com/ho-oto/mathematical-symbols)
    から 4000+ エントリを自動抽出(`src/symbols_ext.rs`、生成物)。結合文字と
    予約グリフは除外。LaTeX 逆引きは厳選テーブル(`SYMBOLS`)のみで、その他の
    Unicode 記号は LaTeX に素通し(unicode-math 前提)。

12. **互換表示モードは撤去(2026-07)** — box-drawing/ASCII に落とす表示専用
    モード(旧 GlyphSet::Compat)を実装したが、「表示だけ変えるモード」は
    正準形式との二重管理コストが高く、フォント問題は合成フォント(§13)で
    解決できるため削除した。必要になれば正準AAを後処理する外部フィルタとして
    再実装する方が筋がよい。

13. **合成フォント生成 (tools/merge_math_font.py)** — もう一つの対策として、
    JuliaMono(数式記号カバレッジが広い等幅フォント)から不足グリフを任意の
    等幅フォントへコピーし、送り幅をベースのセル幅に正確に一致させるスクリプト
    (fontTools 使用)。Menlo で 2400+ グリフ追加・全advance一致を確認済み。

14. **ジャンプとブロック強調はマーカー原子方式** — EasyMotion 風ジャンプ
    (Ctrl+G)とブロック強調(Ctrl+B)は、表示用にクローンした AST へ私用領域
    (U+E0xx)の Sym を挿入し、描画後にラベル/色付き ⟨⟩ へ変換する。レイアウト
    エンジンに座標追跡を追加せずに済み、正準形式にも影響しない。挿入は
    文書順の逆順(ジャンプ)/外側から内側(強調+パス補正)で整合を保つ。

14b. **構造ビュー(Ctrl+O)は「自前パーサの領域トレース」方式** — 全ブロックを
    深さ別背景色で塗る全体表示は、カーソルなし正準描画を `parse_with_regions`
    に通して各領域の矩形+深さを回収して実現(逆変換器があるからこそ可能な
    実装で、レンダラに座標追跡を足さずに正確な矩形が得られる)。

15. **Cancel は結合文字オーバーレイ**(ユーザー提案)— 大きな斜線は
    グリッドでは無理なので、U+0338 を各セルに後置する方式。結合文字を
    かつて却下したのは「独立セルとして幅がない」からだが、既存セルへの
    ゼロ幅付加はむしろ列モデルと相性が良い。Block に疎な (row,col) フラグ
    チャンネルを追加し、パーサは読み込み時に前セルへ折り込む。「最大打ち消し」
    正準形・空スクリプトの正規形からの排除・⬚基線アンカーはすべて
    プロパティテストが見つけた融合反例への対処(30000ケースで検証済み)。

16. **`▶` 基線マーカーは導入後に撤去(2026-07)** — 手書きAAの基線曖昧性の
    解消用に受理していたが、寛容パースの強化(`~` バンド・自由な空白)で
    出番がなくなりユーザー判断で廃止。曖昧な入力は素直にエラーにする。

17. **空白は明示原子 `␣`、Space は入力・Tab が脱出**(ユーザー提案 2026-07)—
    実スペースを正準形に入れると「全高空白列=兄弟の区切り」の構造的意味と
    衝突し全単射性が壊れる(行列セル分割も誤動作する)ため、見た目の空白は
    可視原子 `Sym('␣')` で表す。LaTeX `\ ` / Typst `space`。これに伴い
    自動可読性スペーサ(2Dスクリプト後・バンド両側)は撤去し、間隔調整は
    ユーザーの手に移した(パース必須のスペーサのみ残置、§aa-spec 4)。
    Space キーは ␣ 挿入になったため、インセット脱出は Tab に移動。

18. **`~` は寛容入力のバンド代替 → 導入後に撤去(§25)** — `┄` は手で
    打ちにくいので、パーサだけ `~∑~` 形も受理していた(演算子が BIG_OPS 掲載+
    極限内容ありのときのみ。プロパティテストが `~𝑎̇~` の誤認を発見したため
    演算子制限を導入)。正準形を `~` に変えない理由: `~` は原子としても
    使えるべきで、両立には文脈依存の判別規則が仕様に増える。「曖昧なとき
    だけ区切りを足す」方式も検討したが、正準形が文脈依存になり全単射の
    検証が難しくなるため、正準=`┄`・寛容=`~` の二層で解決した。
    同様に検討した行列の `&` 区切りは、明示空白 ␣(§17)の導入でセル内
    空白が表現可能になったため不要と判断。

19. **Paren/Matrix を Delim/Array に統合**(ユーザー要望 2026-07: langle/rangle・
    左右不一致括弧・middle・array 相当)— `Delim{left,right,mids,segs}` が
    唯一の括弧ノード。行列は「`[ ]` Delim + 素のグリッド Array」に分解され、
    裸の array はヌルデリミタ `╎…┆` が範囲マーカーになる(「括弧に入らない
    array のパース」問題への答え)。学んだこと:
    - グリッドの基線は中央行なので、`⎛⎸╎` 列の基線復元は「内側がグリッドか」
      で分岐が要る(頂点グリフを持つ `⎨⟨` は無条件に頂点=基線)。
    - 左右不一致ペアがあると、両側共有グリフ(`⎪╱╲`)を数えない行単位の
      深さ計数は破綻する → 列を縦に辿って側を解決(`delim_side`)。
    - 「素の行の連続空白は最大2列」という当初の仮定は誤り(演算子余白+
      打ち消しスペーサ+演算子余白で3列)→ グリッド判定は4列閾値。
    いずれもランダムプロパティテスト(30k×4シード)が発見。
    意図的な非対応: グリフの側は固定(`)` を開きに使う `\left)…\right(` 系は
    不可 — 側が可変だと `[a]b]` が二義になる)。仏式半開区間 `]1,2]` は
    原子フォールバックでそのまま通る(自動サイズなし)ので、構造化したい
    場合は `(1,2]` を使う。


20. **要件の捉え直し: AA はソースコード**(ユーザー整理 2026-07)—
    本当に必要なのは「AA でありながら単純にパース可能なフォーマット」であり、
    任意の受理入力に対する `render(parse(aa)) == aa` は要求**ではない**。
    したがって不変条件は次の2つだけ:
    (a) `parse` は受理する全入力上で決定的(1つの絵に2解釈がない)
    (b) `parse(render(normalize(x))) == normalize(x)`(エディタ内容と
        正準出力が往復する — これがないと再編集で壊れる)
    正準形は gofmt の出力のような「整形結果」であって、入力の唯一形ではない。
    帰結として入力の空白は自由: 兄弟間の実スペースは何列でも受理して整形で
    潰す(意味を持たせたい空白は ␣)。**例外は1つ**: デリミタ内の
    「全高空白4列以上」はグリッド区切りとして有意(Python のインデントに
    相当する、この形式唯一の significant whitespace)。
    → この空白個数規則も §22 の格子マーカー化で**全廃**され、例外はゼロに。


21. **格子マーカーと整形スペーサ**(ユーザー提案 2026-07)—
    (a) 裸の \begin{matrix} は `▏▕` だと行列式と紛らわしい、(b) 「1行
    グリッドは空白4列」は空白自由の方針と矛盾、という指摘から:
    裸 Array は**格子マーカー**(区切り交点の `┌┬┐├┼┤└┴┘`、外周含む —
    ユーザー最初のドット格子案の強化版)で自己区切りになり、空白幅の意味は
    完全に消滅した(グリッド証拠は「全幅空白行」のみ。非 `[]` の1行グリッドは
    ␣ 連結に展開)。ユーザー案の「上端だけ `.` にした縦線」「`┄` 交点」は
    どちらも不採用: 前者は基線行が空になり基線駆動パースと両立せず、`.` は
    小数点原子と衝突;後者は格子基線が交点行に載るケースでバンド `┄` と衝突
    する。`┼` 一種類だけでも「同じ高さの格子2つ+間の内容」が融合して読める
    反例があり、角・辺・内部を区別する9グリフに落ち着いた。
    Space キーは **Node::Spacer**(整形空白)に変更: 空白1列を描画し
    LaTeX/Typst に出ず再パースで消える(契約は parse∘render ==
    strip_spacers∘normalize に緩和 — §20 の帰結)。fuzz が見つけた調整:
    行頭 Spacer は ⬚ 基底を壊す・行末 Spacer は打ち消し端と融合する(共に
    正規化で除去)、スクリプト間 Spacer はマージ越しに消す、格子内部は
    ブラケット保護に参加させる、全面打ち消し格子は Cancel に包む。
    ▶ マーカーはユーザー判断で廃止(§16)。

22. **グリッドは格子一本化・空白個数規則の全廃**(ユーザー指摘 2026-07)—
    「スペースの有無は意味を持ってよいが個数で解釈が変わるのは気持ち悪い」
    「`[ ]` だけ行列扱いなのは不統一。裸の行列がベースで、それを伸縮括弧で
    挟むべき」という2指摘への対応。ブランク区切りグリッド(空白2列=セル
    区切り)を**廃止**し、Array はどこでも格子(§aa-spec Array)で描く。
    帰結: `[ ]` の特別扱い(常時グリッド・1×1包み・1行スプライス・␣連結)、
    グリッド判定、`delim_interior_baseline` がすべて消え、仕様から
    「空白の個数」に依存する規則がゼロになった。矢印も同原理で `─` 胴体+
    先端の maximal munch に統一(`───→`=矢印、`─── →`=分数+原子。
    専用胴体 `╌` は不要になり削除)。
    「縦に `.` を並べる」当初案を採らない理由(再掲): `.` は小数点原子
    なので、上付き・下付きに `.` が現れると格子マーカーと区別できない
    (例: `x^{.}_{.}` の縦並び)。加えて基線行が空になる列はパーサが
    接地できない。格子グリフはこの「予約文字版のドット」である。

23. **デリミタ×格子の融合形 → 最小マーカー化**(ユーザー要望 2026-07:
    `⎢├` の並びが不格好 → さらに「┼ があれば ┬┴ は冗長」)— デリミタの
    単独 seg が Array のとき格子の縁列をデリミタ列が吸収し、マーカーは
    必要最小限: 複数行×複数列は「空白+┼ のみの区切り行」、1行は ┬┴ 行、
    1列は ┠┨ 接合。2×2 が3行に収まり、旧形・枠付き格子包みも合法入力の
    まま整形で最小形へ。「純粋な行」検出は ┼ が予約文字だから健全
    (入れ子は必ず他グリフを同じ行に落とす)。┠ の族解決は列walk。
    1×1 は識別不能なので素の行へ正規化。⟨⟩ は頂点幾何と衝突するため
    融合対象外。

24. **バンドの一般化 `┄piece┄…┄`**(ユーザー提案 2026-07)— 「スペース
    なしで ┄ に挟まれたものはバンド」という一貫規則に拡張し、`┄lim┄`
    `┄arg┄max┄` で \lim・\argmax 系の下極限が実現(ロードマップの
    \lim 項目もこれで解決)。AST は `BigOp{base: Row}` に一般化。
    空極限の BigOp は正規形から消え(base を行に展開)、裸 `∑` の
    昇格規則も削除できた。バンド端は空白1で隣と区切る(貪欲に読む文法の
    構造的要請 — かつて見た目用に入れて撤去したスペーサが必須として復活)。
    `~` 寛容バンドも同様に一般化したが、直後に撤去(§25)。
    エディタは lim/max/min/sup/inf/det/gcd/Pr が下極限に入り、
    \argmax/\argmin は定型の複数ピース基底(`┄arg┄max┄`)を挿入する
    (任意基底の編集 UI はロードマップ)。

25. **`~` 寛容バンドの撤去と「黙って捨てない」原則(2026-07)** —
    仕様点検で、`~` バンドは (a) 一般化後は「既知の演算子のみ」という
    例外規則を仕様に残す、(b) 受理形と誤読形の距離が近い(`~a~b~` が
    原子列としても読めてしまい、失敗がエラーでなく誤変換になる)ことが
    判明し、正準 `┄` 一本に戻した。`~` はただの原子。あわせて、基線上の
    トークンの真上・真下に(アクセント以外の)内容が重なった手書き入力は
    **パースエラー**にした — 以前は黙って捨てられ「変換成功なのに内容
    欠落」が起き得た。寛容パースの原則: 受理を広げるのは読みが一意な
    形だけで、内容を落とす受理はしない。

26. **キーマップの一本化とキー駆動テスト(2026-07)** — TUI(crossterm)と
    wasm(DOM KeyboardEvent)が同じキー割当を別々に実装してドリフトして
    いたため、host 非依存の `Key`/`Effect` と `Editor::input` に統合
    (`src/input.rs`)。ホスト側は変換と Effect(保存・コピー・終了)の
    実行だけ。tests/ui.rs にキースクリプト DSL とランダムキー列の
    プロパティテスト(毎打鍵でラウンドトリップ検査 = TUI ガードの CI 化)
    を追加。導入初日にランダムキー列が2つの実バグを発見:
    (a) 原子の `)` がデリミタ内で左右不一致ペア走査に食われて読みがずれる
    → ASCII 括弧 `( ) [ ]` も原子禁止に統一(close_paren は挿入せず
    メッセージ、対応の取れない閉じ括弧はパースエラー)。
    (b) 選択アンカーが行をまたいで生存し、行が縮むと drain が範囲外
    パニック → アンカーに設定時パスを持たせ、行を離れた選択は無効化。

27. **編集 UX の磨き込み第1弾(ユーザー要望 2026-07)** — (a) `[` の
    特別扱いを廃止し `( {` と同じ自動サイズ括弧キーに(格子統一 §21 以降
    は行列予約の理由が消えていた。`]` の行列脱出は維持)。(b) Ctrl+B
    ブロック強調は Ctrl+O 構造ビューに実質包含されていたため撤去。
    (c) `//` で分数(`/` 2連打。リテラルは `/ /` から空白を消す)。
    (d) 選択の ^C/^X/^V(エディタ内部クリップボード、カット+ペースト=
    移動)。(e) Shift+↑ で選択を親構造へ拡大(トップでは数式全体)。
    (f) デリミタ指定を Typst 風 `\lr` に統一(視覚順: 左 [|…] 右。
    1文字スペックと `\langle` 等の名前を混在可。`\delim` は別名。
    非スペックの `lr…` は記号名にフォールバック)。(g) ヘルプ行を状況
    依存に(グリッド内は増減コマンド、デリミタ内は `\mid` 等を表示)。
    発見性の問題(middle・行列増減の入力方法が分からない)はキーの追加
    ではなく文脈ヒントで解決する方針。

28. **ブロック選択モードと \op/\op*(ユーザー要望 2026-07)** —
    (a) Ctrl+B 復活、ただし旧「強調表示」ではなく**選択**: 構造ブロックに
    ジャンプ式のラベルを振り、ラベルキーで丸ごと選択(Ctrl+O の色分けと
    対になる操作系。^C/^X・包み込み・削除に接続)。(b) `\op<name>` =
    \operatorname は AST 上 Text{math}(=\rm と同一。'…'=rm / "…"=text
    の裁定より新ノード不要)、`\op*<name>` = \operatorname* は
    Text 基底の BigOp(`┄name┄` バンド)。LaTeX は基底が単独 Text の
    BigOp を \operatorname*{…} に、Typst は op("…", limits: #true) に
    直列化(\mathrm のままだと極限が横に付いてしまうため)。

29. **ラベルは挿入せず重ね書き・^G の候補絞り込み(ユーザー要望 2026-07)**
    — ラベル/マーカー原子を列として挿入すると数式のレイアウトがずれる
    ため、表示時に**全マーカー列を除去**して元のジオメトリに戻し、
    ラベル文字は直後の文字の上に重ね書きする方式へ(main.rs
    `marker_boxes` に統合。ブロックの背景色ボックスも同じ機構)。
    ^G は候補が多すぎたため最大16個(`Editor::JUMP_MAX`)に絞る。
    配分は「空スロット(未入力フィールド)最優先(枠の半分まで)+
    カーソルの左右それぞれで遠端から距離を半減させる等比アンカー列
    (L, L/2, …, 1)。予算超過時は最寄りと最遠を残して中間の冗長な
    ものから間引く」— 近距離の微調整と遠距離への大ジャンプを同時に
    1打鍵で賄う(当初の「近い順に8個」は遠くへ飛べなかった)。
    候補は全カーソル位置(walk を列→子→次の列の真の文書順に変更し、
    列挙順を距離の近似として使う)。その後の調整: 上限16に増量、
    優先順位は「空スロット(≤半分)→グリッドのセル末尾(隣のセルを
    いじる操作が頻出のため。カーソルのいるグリッド優先、等比枠を
    4つ確保)→等比アンカー」。選択中の ←/→ は選択の左右端への集約、
    ^A は数式先頭へのジャンプ。

30. **マウスによるカーソル移動(2026-07)** — TUI でマウスキャプチャを
    有効化し、クリック位置に最も近い編集位置へ移動(wasm にも
    `click(x, y)` を公開)。逆写像(セル座標→カーソル位置)は
    **プローブ方式**: 各候補位置にカーソルを置いた描画で ▌ が出る
    セルを求め、クリック座標との最近傍を選ぶ(`Editor::click`)。
    カーソル列の挿入でプローブと表示のレイアウトが±1列ずれ得るため
    厳密ではないが、クリック用途には十分。厳密化はロードマップの
    「レンダラとビューの分離」(レンダラが位置マップを出力)で行う。
    ratatui の描画は `draw_canvas` が数式左上のスクリーン座標を返し、
    イベント側で引き算する。副作用: 端末ネイティブのテキスト選択は
    Shift+ドラッグが必要になる。

31. **裸の大型演算子の ↑/↓ 昇格(バグ報告 2026-07)** — 極限が空の
    バンドは正準形に存在しない(§24)ため、--session 復元などの
    正規化経路を通ると裸の ∑ / lim 原子になり、UI から二度と極限に
    入れなくなっていた。↑/↓ がカーソル直前の大型演算子原子
    (bigop_by_char / LIMIT_FUNCS)を BigOp に昇格して極限へ入る
    ようにして解消。

32. **カーソルの幅ゼロ化(ユーザー指摘 2026-07: 「カーソル移動で位置が
    チラチラ動くのは必要か? 文字に重なる普通の端末スタイルでよいのでは」)**
    — ▌ を1列のブロックとして挿入する方式は、挿入列が中央寄せの丸めを
    変え、カーソル移動のたびにレイアウトが±1列揺れていた(表示側の列剥がし
    でも「消せない列」が残るケースがある)。`Block` に `caret:
    Option<(row, col)>`(挿入点の右のセル座標)を追加し、cancel 座標と
    同じオフセット計算で全合成に伝搬させる方式へ全面移行。カーソルは
    もう列を占有せず、**表示ジオメトリはカーソル無し描画と常に同一**。
    TUI は該当セルを反転表示(端末標準のブロックカーソル)、空スロットは
    ⬚ のセルに caret が乗る。wasm のテキスト画面のみ ▌ をセルに上書き。
    副産物: マウスのプローブ照合が厳密になった(プローブのジオメトリが
    表示と一致するため)。伝搬漏れは tests/ui.rs のランダムキー列が
    毎打鍵「caret 生存」で検出する。

33. **表示装飾の完全幅ゼロ化(バグ報告 2026-07: 編集ビューと素のビューの
    差で ^B がズレ・^G がチカチカ)** — ラベル/選択マーカーの原子は
    サブ行に入るとバンド幅や中央寄せ自体を変え、表示側の列剥がしでは
    復元できない(∑ とラベルが同一列を共有する等)。§32 の caret と
    同じ方式に統一: マーカー原子は**幅ゼロで描画**され、`Block.marks`
    (row, col, char)として cancel と同じオフセット計算で全合成に伝搬。
    fuse 規則・行頭 ⬚ 判定にも透明。表示側は marks を読んでラベルの
    重ね書きと背景ボックス(入れ子深さはターゲットのパス長)を塗るだけで、
    列の挿入も削除も一切ない。さらに ^G/^B 中もカーソルをパス補正付きで
    描画に通し(decorated の bump)、**モード表示は常に編集ビューと同一
    ジオメトリ**(空極限の ⬚・非融合行列・2D 展開スクリプトも保たれる)。
    回帰: bin テストが ∑/行列/² の3形で
    「^G/^B 出入りでセル不変(ラベル重ね以外)」を検証。^B の融合行列は
    「Delim の単独 seg の Array はターゲット外(囲む Delim で選ぶ)」。
    マーカーはレンダラの**判断ロジックにも透明**(インライン上付きの
    2D 展開条件・融合グリッドの単独 seg 条件・行頭 ⬚ 判定・fuse 規則は
    マーカーを無視する)。唯一の例外は**不可視スロットの実体化**: 空極限
    などラベルの置き場が無いスロットは ^G 中だけ ⬚ として現れる(これは
    必要なズレ)。そのため ^G 解除時は空スロットを**ゴースト ⬚**
    (`SLOT_GHOST` マーカー)として次の入力まで残す — ユーザー提案の
    凍結方式。再度 ^G を押すと同一ジオメトリにラベルが乗るだけで、
    カーソル移動などの実入力で初めて通常表示に戻る。

34. **ジャンプ v2 実装(2026-07)** — docs/jump-spec.md の通り。物理
    座標は「全候補に幅ゼロのプローブマーク(U+F000+idx)を打った1回の
    レンダリング」で取得(表示とジオメトリが一致するので厳密。クリック
    の逆写像も同じ表に置き換え、プローブ連打を廃止)。マーカーはランク
    文字(U+E100+rank)で挿入し、表示側でラベル(61個)/無ラベルの印/
    選択ハイライトに復号。^G 中の矢印キーは選択マーカー移動、Enter で
    確定。旧 JUMP_MAX・等比アンカーは撤去。

35. **^F フリーカーソルモード(ユーザー提案 2026-07)** — 既定の矢印
    移動を置き換えるのではなく、専用モードで物理座標の自由移動を提供。
    矢印でセル単位に移動し、毎ステップ最寄りの編集可能位置(スナップ先)
    を座標表で計算して両方表示(自由カーソル=色付きセル、スナップ先=
    通常カーソル)。Enter で確定、Esc で元の位置。最近傍計算はクリック
    と共通(`nearest_position`)。
    追補: **未展開要素の自動展開** — 自由カーソルが未展開のインライン
    添え字や不可視スロットに近づくと、ゴースト機構でその場で展開する。
    振動対策(ユーザー指摘)は3点: (a) **ヒステリシス**(展開 R_IN=3、
    畳み R_OUT=8)、(b) 近接判定は展開で動かない**可視アンカー**(親行の
    ノード直前位置)を今の表示フレームで測る、(c) 展開でキャンバスが
    ずれたら**直前のスナップ先を基準に自由カーソルを平行移動**して
    内容に貼り付ける(re-anchor)。座標表はすべて「表示フレーム」
    (`display_coords` — ゴースト実体化+可視位置のみプローブ)で統一し、
    クリック/スナップが画面と厳密に一致するようになった(以前の全展開
    プローブは廃止)。

36. **複数行数式(ユーザー提案 2026-07)** — `Node::Break`(ルート行の
    改行原子)を追加。正準AAは各行ブロックを左揃えで縦積みし、行の間に
    **`┄` 1文字だけの区切り行**を挟む(ユーザー指定の形。バンドは piece を
    密着で挟むため、単体 ┄ だけの行は1つの数式の中に現れず衝突ゼロ)。
    パースは単体 ┄ 行で分割し、各セグメントを独立の数式として通常の
    基線推定で読む — 初版の「継続行の基線に `┄ ` プレフィクス」案は
    マーカーが基線を教える利点があったが、プレフィクスが偶然基線行を
    非空白にして「Spacer 基底のスクリプト行頭チャンク(基線行が全空白)」を
    覆い隠していた。正しい対処として normalize が**行端(Break 前後)の
    Spacer を落とす**ようにし(行頭スクリプトの ⬚ 基底が必ず実体化)、
    セグメントは常に独立の正準数式=基線推定可能になった。align はやらない。
    エディタ: トップレベル Enter=改行、Home/End は行単位、↑/↓ は
    縦ターゲットが無ければどの深さからも行間移動(display_coords で
    列位置を最寄り保持)、行頭 Backspace で行結合。レンダは render_root
    (Break 分割+vstack)がトップレベル専用入口になり、既存の render_row
    は行内・入れ子用。LaTeX `\\` / Typst `\ `。
    ロードマップの「複数行対応」を消化(数式番号は未)。

37. **ヌルデリミタのグリフ ╎ ┆(ユーザー裁定 2026-07)** — `\left.`/
    `\right.` 相当の柱を `▏ ▕`(1/8ブロック)から破線の `╎`(左,
    U+254E)/ `┆`(右, U+2506)に変更。「そこに壁はない」ことを `┄`
    (バンド・行区切り)と同じ破線=幽霊系で表す。旧グリフは入力として
    受理し fmt が直す。cases は従来どおり「配列は隣接する柱と融合」
    (⎧+┼+右┆列)を維持 — 一時実装した「ヌル側は配列自身の格子縁
    ┐┤┘ を見せる」案は、ヌル列が基線上で不可視になり(セル行が空白)、
    デリミタ照合が行単位の対称性を失って複雑化するため撤回。柱が
    全行を占める現行形はパースの「行を横切る対の深度計数」と相性が
    良く、`\right.` が見えない LaTeX との差は破線化で埋める。
