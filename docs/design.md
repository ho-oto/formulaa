# mascii 設計文書

## ビジョン

プレーンテキストの世界で数式を第一級に扱う。人間が読める 2D アスキーアート
(Unicode 数式記号優先)と数式 AST が**決定論的に相互変換**できれば:

- AA のまま考え、機械的に LaTeX / Typst / MathML に変換できる
- 「AA は後から編集しづらい」という問題は CLI ツール(parse → 構造編集 →
  re-render)を挟むだけで解消する
- TUI エディタ(LyX 風)は AST を直接編集する快適なフロントエンドになる

このため内部表現は TeX 文字列ではなく **AST**(`src/ast.rs`)であり、
2D レンダリング・LaTeX/Typst 出力・構造編集のすべてを AST から導出する。

## アーキテクチャ

```
                    ┌────────────┐
   TUI editor ────▶ │            │ ──▶ render.rs ──▶ 正準AA (canonical)
  (editor.rs)       │    AST     │ ◀── parse.rs  ◀── AA テキスト
                    │  (ast.rs)  │ ──▶ latex.rs  ──▶ LaTeX
                    │            │ ──▶ typst.rs  ──▶ Typst
                    └────────────┘
   symbols.rs / symbols_ext.rs: コマンド名 ⇄ Unicode(4000+ 記号)
```

- `render.rs` と `parse.rs` は正準AA仕様(docs/aa-spec.md)の表と裏。
  **必ず同時に変更し、`tests/roundtrip.rs` を通すこと。**
- カーソル = 「入れ子 Row へのパス + 列」(LyX と同じモデル)。
- 正しさの根拠はラウンドトリップ性:
  `parse(render(normalize(x))) == normalize(x)`(実式コーパス + ランダム生成
  2000 ケースのプロパティテストで検証)。

## 主要な設計判断と経緯

1. **AST を最初から内部表現にする**(TeX 文字列を持たない)
   — 構造編集にはどのみち AST が必要で、AA⇄AST 一対一対応という最終目標への
   一本道のため。

2. **Unicode 積極使用** — `x²` `aᵢ` などのインライン上付き・下付き、数学
   イタリック体(`𝑥`)、`−` `⋅` などは**別コードポイント**なので、見た目が
   良くなるだけでなく曖昧性を根本から消す(tex2utf 系の純ASCII AA より
   パースが簡単になる)。

3. **上下極限のバンド記法 `┈┈∑┈┈`** — 無標識の上下極限は原理的に非可逆:
   `∑_{n=1}^{∫}` と `∫_{∑_{n=1}}` が同一の絵になる反例を実レンダラで確認した
   (`examples/ambig.rs` に保存)。ユーザー提案の「範囲標識 `~~~X~~~`」を
   基線上のバンドとして洗練し、分数罫線と同じ「範囲+基線」の二役を持たせた。
   極限が両方空なら裸の `∫` のまま(バンドなし)。

4. **compact(詰め)組版 → 全面撤去(2026-07)** — 当初は display モードで
   二項演算子の前後に空白1を自動挿入し、スクリプト引数・極限・行列セルのみ
   詰め組み(scriptstyle 相当)としていた。整形 Spacer(§21)で手動の間隔
   調整が可能になったため、ユーザー判断で自動演算子空白ごと廃止。
   二層組版の区別が消えて仕様・実装とも単純化し、LaTeX/Typst 出力の組版は
   元々ツール側の仕事なので失うものがない。

5. **`⬚` 明示基底** — 行頭のスクリプト(`[Sup(x)]`)は `⬚ˣ` と描画。
   空行 `[]` との衝突を防ぐ。空の必須スロットも `⬚`。

6. **アクセントは 2D マーク**(Unicode 結合文字は不採用 — グリッドの列モデル
   を壊すため)。基底の真上/真下のセルは他の何にも使われない空き地なので
   1 セル検査でパースできる。マーク文字は原子と互いに素な予約集合
   (`~`→`˜`, `→`→`⇀` など)とし、上マークと下マークも互いに素にすることで
   「左端列に2文字が縦に並んだときの基線」も一意に決まる(ユーザー指摘)。

7. **行列は `⎡⎤` + 空白帯区切り** — `( )` との区別のため丸括弧行列は
   採用しない(`(x)` の 1×1 行列と括弧の衝突)。列区切り空白2列・行区切り
   空白1行。入れ子行列はブラケット保護(いずれかの行でブラケット対の内側に
   ある列は区切りにしない)で守る。

8. **sin/cos は立体、変数はイタリック** — 描画時イタリック化のおかげで
   立体英字列=関数名が無曖昧。正準形式はイタリック固定(Ctrl+T は表示専用)。

9. **無条件マージン廃止 → バー接触時のみスペーサ** — 当初 Frac/BigOp に
   常時1列マージンを付けたが、スクリプト引数内部に「全高空白列」を作り、
   外側から見た分割を壊すことがプロパティテストで判明。空白列は「同一基線の
   兄弟の区切り」しか意味しないよう、`──`/`┈┈` が接触する場合のみ空白1列を
   挿入する規則に変更(分割されても normalize の合流で正しく復元される)。

10. **normalize(正規形)** — `Sup(a);Sup(b)` と `Sup(a++b)` は同じ絵になる
    ため、隣接同種スクリプトを合流した形を正規形とし、パーサは正規形のみを
    返す。合流が新たな隣接を生むため合流後に再正規化(冪等性が必要 —
    プロパティテストで発見したバグ)。

11. **記号カバレッジ** — ユーザー製 VSCode 拡張
    [ho-oto/mathematical-symbols](https://github.com/ho-oto/mathematical-symbols)
    から 4000+ エントリを自動抽出(`src/symbols_ext.rs`、生成物)。結合文字と
    予約グリフは除外。LaTeX 逆引きは厳選テーブル(`SYMBOLS`)のみで、その他の
    Unicode 記号は LaTeX に素通し(unicode-math 前提)。

12. **互換表示モードは撤去(2026-07)** — box-drawing/ASCII に落とす表示専用
    モード(旧 GlyphSet::Compat)を実装したが、「表示だけ変えるモード」は
    正準形式との二重管理コストが高く、フォント問題は合成フォント(§13)で
    解決できるため削除した。必要になれば正準AAを後処理する外部フィルタとして
    再実装する方が筋がよい。

13. **合成フォント生成 (tools/merge_math_font.py)** — もう一つの対策として、
    JuliaMono(数式記号カバレッジが広い等幅フォント)から不足グリフを任意の
    等幅フォントへコピーし、送り幅をベースのセル幅に正確に一致させるスクリプト
    (fontTools 使用)。Menlo で 2400+ グリフ追加・全advance一致を確認済み。

14. **ジャンプとブロック強調はマーカー原子方式** — EasyMotion 風ジャンプ
    (Ctrl+G)とブロック強調(Ctrl+B)は、表示用にクローンした AST へ私用領域
    (U+E0xx)の Sym を挿入し、描画後にラベル/色付き ⟨⟩ へ変換する。レイアウト
    エンジンに座標追跡を追加せずに済み、正準形式にも影響しない。挿入は
    文書順の逆順(ジャンプ)/外側から内側(強調+パス補正)で整合を保つ。

14b. **構造ビュー(Ctrl+O)は導入後に撤去(2026-07)** — ^B のブロック選択(深さ色ボックス)で用が足りるというユーザー判断で廃止。実装方式の記録: — 全ブロックを
    深さ別背景色で塗る全体表示は、カーソルなし正準描画を `parse_with_regions`
    に通して各領域の矩形+深さを回収して実現(逆変換器があるからこそ可能な
    実装で、レンダラに座標追跡を足さずに正確な矩形が得られる)。

15. **Cancel は結合文字オーバーレイ**(ユーザー提案)— 大きな斜線は
    グリッドでは無理なので、U+0338 を各セルに後置する方式。結合文字を
    かつて却下したのは「独立セルとして幅がない」からだが、既存セルへの
    ゼロ幅付加はむしろ列モデルと相性が良い。Block に疎な (row,col) フラグ
    チャンネルを追加し、パーサは読み込み時に前セルへ折り込む。「最大打ち消し」
    正準形・空スクリプトの正規形からの排除・⬚基線アンカーはすべて
    プロパティテストが見つけた融合反例への対処(30000ケースで検証済み)。

16. **`▶` 基線マーカーは導入後に撤去(2026-07)** — 手書きAAの基線曖昧性の
    解消用に受理していたが、寛容パースの強化(`~` バンド・自由な空白)で
    出番がなくなりユーザー判断で廃止。曖昧な入力は素直にエラーにする。

17. **空白は明示原子 `␣`、Space は入力・Tab が脱出**(ユーザー提案 2026-07)—
    実スペースを正準形に入れると「全高空白列=兄弟の区切り」の構造的意味と
    衝突し全単射性が壊れる(行列セル分割も誤動作する)ため、見た目の空白は
    可視原子 `Sym('␣')` で表す。LaTeX `\ ` / Typst `space`。これに伴い
    自動可読性スペーサ(2Dスクリプト後・バンド両側)は撤去し、間隔調整は
    ユーザーの手に移した(パース必須のスペーサのみ残置、§aa-spec 4)。
    Space キーは ␣ 挿入になったため、インセット脱出は Tab に移動。

18. **`~` は寛容入力のバンド代替 → 導入後に撤去(§25)** — `┈` は手で
    打ちにくいので、パーサだけ `~∑~` 形も受理していた(演算子が BIG_OPS 掲載+
    極限内容ありのときのみ。プロパティテストが `~𝑎̇~` の誤認を発見したため
    演算子制限を導入)。正準形を `~` に変えない理由: `~` は原子としても
    使えるべきで、両立には文脈依存の判別規則が仕様に増える。「曖昧なとき
    だけ区切りを足す」方式も検討したが、正準形が文脈依存になり全単射の
    検証が難しくなるため、正準=`┈`・寛容=`~` の二層で解決した。
    同様に検討した行列の `&` 区切りは、明示空白 ␣(§17)の導入でセル内
    空白が表現可能になったため不要と判断。

19. **Paren/Matrix を Delim/Array に統合**(ユーザー要望 2026-07: langle/rangle・
    左右不一致括弧・middle・array 相当)— `Delim{left,right,mids,segs}` が
    唯一の括弧ノード。行列は「`[ ]` Delim + 素のグリッド Array」に分解され、
    裸の array はヌルデリミタ `╎…┆` が範囲マーカーになる(「括弧に入らない
    array のパース」問題への答え)。学んだこと:
    - グリッドの基線は中央行なので、`⎛⎸╎` 列の基線復元は「内側がグリッドか」
      で分岐が要る(頂点グリフを持つ `⎨⟨` は無条件に頂点=基線)。
    - 左右不一致ペアがあると、両側共有グリフ(`⎪╱╲`)を数えない行単位の
      深さ計数は破綻する → 列を縦に辿って側を解決(`delim_side`)。
    - 「素の行の連続空白は最大2列」という当初の仮定は誤り(演算子余白+
      打ち消しスペーサ+演算子余白で3列)→ グリッド判定は4列閾値。
    いずれもランダムプロパティテスト(30k×4シード)が発見。
    意図的な非対応: グリフの側は固定(`)` を開きに使う `\left)…\right(` 系は
    不可 — 側が可変だと `[a]b]` が二義になる)。仏式半開区間 `]1,2]` は
    原子フォールバックでそのまま通る(自動サイズなし)ので、構造化したい
    場合は `(1,2]` を使う。


20. **要件の捉え直し: AA はソースコード**(ユーザー整理 2026-07)—
    本当に必要なのは「AA でありながら単純にパース可能なフォーマット」であり、
    任意の受理入力に対する `render(parse(aa)) == aa` は要求**ではない**。
    したがって不変条件は次の2つだけ:
    (a) `parse` は受理する全入力上で決定的(1つの絵に2解釈がない)
    (b) `parse(render(normalize(x))) == normalize(x)`(エディタ内容と
        正準出力が往復する — これがないと再編集で壊れる)
    正準形は gofmt の出力のような「整形結果」であって、入力の唯一形ではない。
    帰結として入力の空白は自由: 兄弟間の実スペースは何列でも受理して整形で
    潰す(意味を持たせたい空白は ␣)。**例外は1つ**: デリミタ内の
    「全高空白4列以上」はグリッド区切りとして有意(Python のインデントに
    相当する、この形式唯一の significant whitespace)。
    → この空白個数規則も §22 の格子マーカー化で**全廃**され、例外はゼロに。


21. **格子マーカーと整形スペーサ**(ユーザー提案 2026-07)—
    (a) 裸の \begin{matrix} は `▏▕` だと行列式と紛らわしい、(b) 「1行
    グリッドは空白4列」は空白自由の方針と矛盾、という指摘から:
    裸 Array は**格子マーカー**(区切り交点の `┌┬┐├┼┤└┴┘`、外周含む —
    ユーザー最初のドット格子案の強化版)で自己区切りになり、空白幅の意味は
    完全に消滅した(グリッド証拠は「全幅空白行」のみ。非 `[]` の1行グリッドは
    ␣ 連結に展開)。ユーザー案の「上端だけ `.` にした縦線」「`┈` 交点」は
    どちらも不採用: 前者は基線行が空になり基線駆動パースと両立せず、`.` は
    小数点原子と衝突;後者は格子基線が交点行に載るケースでバンド `┈` と衝突
    する。`┼` 一種類だけでも「同じ高さの格子2つ+間の内容」が融合して読める
    反例があり、角・辺・内部を区別する9グリフに落ち着いた。
    Space キーは **Node::Spacer**(整形空白)に変更: 空白1列を描画し
    LaTeX/Typst に出ず再パースで消える(契約は parse∘render ==
    strip_spacers∘normalize に緩和 — §20 の帰結)。fuzz が見つけた調整:
    行頭 Spacer は ⬚ 基底を壊す・行末 Spacer は打ち消し端と融合する(共に
    正規化で除去)、スクリプト間 Spacer はマージ越しに消す、格子内部は
    ブラケット保護に参加させる、全面打ち消し格子は Cancel に包む。
    ▶ マーカーはユーザー判断で廃止(§16)。

22. **グリッドは格子一本化・空白個数規則の全廃**(ユーザー指摘 2026-07)—
    「スペースの有無は意味を持ってよいが個数で解釈が変わるのは気持ち悪い」
    「`[ ]` だけ行列扱いなのは不統一。裸の行列がベースで、それを伸縮括弧で
    挟むべき」という2指摘への対応。ブランク区切りグリッド(空白2列=セル
    区切り)を**廃止**し、Array はどこでも格子(§aa-spec Array)で描く。
    帰結: `[ ]` の特別扱い(常時グリッド・1×1包み・1行スプライス・␣連結)、
    グリッド判定、`delim_interior_baseline` がすべて消え、仕様から
    「空白の個数」に依存する規則がゼロになった。矢印も同原理で `─` 胴体+
    先端の maximal munch に統一(`───→`=矢印、`─── →`=分数+原子。
    専用胴体 `╌` は不要になり削除)。
    「縦に `.` を並べる」当初案を採らない理由(再掲): `.` は小数点原子
    なので、上付き・下付きに `.` が現れると格子マーカーと区別できない
    (例: `x^{.}_{.}` の縦並び)。加えて基線行が空になる列はパーサが
    接地できない。格子グリフはこの「予約文字版のドット」である。

23. **デリミタ×格子の融合形 → 最小マーカー化**(ユーザー要望 2026-07:
    `⎢├` の並びが不格好 → さらに「┼ があれば ┬┴ は冗長」)— デリミタの
    単独 seg が Array のとき格子の縁列をデリミタ列が吸収し、マーカーは
    必要最小限: 複数行×複数列は「空白+┼ のみの区切り行」、1行は ┬┴ 行、
    1列は ┠┨ 接合。2×2 が3行に収まり、旧形・枠付き格子包みも合法入力の
    まま整形で最小形へ。「純粋な行」検出は ┼ が予約文字だから健全
    (入れ子は必ず他グリフを同じ行に落とす)。┠ の族解決は列walk。
    1×1 は識別不能なので素の行へ正規化。⟨⟩ は頂点幾何と衝突するため
    融合対象外。

24. **バンドの一般化 `┈piece┈…┈`**(ユーザー提案 2026-07)— 「スペース
    なしで ┈ に挟まれたものはバンド」という一貫規則に拡張し、`┈lim┈`
    `┈arg┈max┈` で \lim・\argmax 系の下極限が実現(ロードマップの
    \lim 項目もこれで解決)。AST は `BigOp{base: Row}` に一般化。
    空極限の BigOp は正規形から消え(base を行に展開)、裸 `∑` の
    昇格規則も削除できた。バンド端は空白1で隣と区切る(貪欲に読む文法の
    構造的要請 — かつて見た目用に入れて撤去したスペーサが必須として復活)。
    `~` 寛容バンドも同様に一般化したが、直後に撤去(§25)。
    エディタは lim/max/min/sup/inf/det/gcd/Pr が下極限に入り、
    \argmax/\argmin は定型の複数ピース基底(`┈arg┈max┈`)を挿入する
    (任意基底の編集 UI はロードマップ)。

25. **`~` 寛容バンドの撤去と「黙って捨てない」原則(2026-07)** —
    仕様点検で、`~` バンドは (a) 一般化後は「既知の演算子のみ」という
    例外規則を仕様に残す、(b) 受理形と誤読形の距離が近い(`~a~b~` が
    原子列としても読めてしまい、失敗がエラーでなく誤変換になる)ことが
    判明し、正準 `┈` 一本に戻した。`~` はただの原子。あわせて、基線上の
    トークンの真上・真下に(アクセント以外の)内容が重なった手書き入力は
    **パースエラー**にした — 以前は黙って捨てられ「変換成功なのに内容
    欠落」が起き得た。寛容パースの原則: 受理を広げるのは読みが一意な
    形だけで、内容を落とす受理はしない。

26. **キーマップの一本化とキー駆動テスト(2026-07)** — TUI(crossterm)と
    wasm(DOM KeyboardEvent)が同じキー割当を別々に実装してドリフトして
    いたため、host 非依存の `Key`/`Effect` と `Editor::input` に統合
    (`src/input.rs`)。ホスト側は変換と Effect(保存・コピー・終了)の
    実行だけ。tests/ui.rs にキースクリプト DSL とランダムキー列の
    プロパティテスト(毎打鍵でラウンドトリップ検査 = TUI ガードの CI 化)
    を追加。導入初日にランダムキー列が2つの実バグを発見:
    (a) 原子の `)` がデリミタ内で左右不一致ペア走査に食われて読みがずれる

29. **ラベルは挿入せず重ね書き・^G の候補絞り込み(ユーザー要望 2026-07)**
    — ラベル/マーカー原子を列として挿入すると数式のレイアウトがずれる
    ため、表示時に**全マーカー列を除去**して元のジオメトリに戻し、
    ラベル文字は直後の文字の上に重ね書きする方式へ(main.rs
    `marker_boxes` に統合。ブロックの背景色ボックスも同じ機構)。
    ^G は候補が多すぎたため最大16個(`Editor::JUMP_MAX`)に絞る。
    配分は「空スロット(未入力フィールド)最優先(枠の半分まで)+
    カーソルの左右それぞれで遠端から距離を半減させる等比アンカー列
    (L, L/2, …, 1)。予算超過時は最寄りと最遠を残して中間の冗長な
    ものから間引く」— 近距離の微調整と遠距離への大ジャンプを同時に
    1打鍵で賄う(当初の「近い順に8個」は遠くへ飛べなかった)。
    候補は全カーソル位置(walk を列→子→次の列の真の文書順に変更し、
    列挙順を距離の近似として使う)。その後の調整: 上限16に増量、
    優先順位は「空スロット(≤半分)→グリッドのセル末尾(隣のセルを
    いじる操作が頻出のため。カーソルのいるグリッド優先、等比枠を
    4つ確保)→等比アンカー」。選択中の ←/→ は選択の左右端への集約、
    ^A は数式先頭へのジャンプ。

33. **表示装飾の完全幅ゼロ化(バグ報告 2026-07: 編集ビューと素のビューの
    差で ^B がズレ・^G がチカチカ)** — ラベル/選択マーカーの原子は
    サブ行に入るとバンド幅や中央寄せ自体を変え、表示側の列剥がしでは
    復元できない(∑ とラベルが同一列を共有する等)。§32 の caret と
    同じ方式に統一: マーカー原子は**幅ゼロで描画**され、`Block.marks`
    (row, col, char)として cancel と同じオフセット計算で全合成に伝搬。
    fuse 規則・行頭 ⬚ 判定にも透明。表示側は marks を読んでラベルの
    重ね書きと背景ボックス(入れ子深さはターゲットのパス長)を塗るだけで、
    列の挿入も削除も一切ない。さらに ^G/^B 中もカーソルをパス補正付きで
    描画に通し(decorated の bump)、**モード表示は常に編集ビューと同一
    ジオメトリ**(空極限の ⬚・非融合行列・2D 展開スクリプトも保たれる)。
    回帰: bin テストが ∑/行列/² の3形で
    「^G/^B 出入りでセル不変(ラベル重ね以外)」を検証。^B の融合行列は
    「Delim の単独 seg の Array はターゲット外(囲む Delim で選ぶ)」。
    マーカーはレンダラの**判断ロジックにも透明**(インライン上付きの
    2D 展開条件・融合グリッドの単独 seg 条件・行頭 ⬚ 判定・fuse 規則は
    マーカーを無視する)。唯一の例外は**不可視スロットの実体化**: 空極限
    などラベルの置き場が無いスロットは ^G 中だけ ⬚ として現れる(これは
    必要なズレ)。そのため ^G 解除時は空スロットを**ゴースト ⬚**
    (`SLOT_GHOST` マーカー)として次の入力まで残す — ユーザー提案の
    凍結方式。再度 ^G を押すと同一ジオメトリにラベルが乗るだけで、
    カーソル移動などの実入力で初めて通常表示に戻る。

    基線推定で読む — 初版の「継続行の基線に `┈ ` プレフィクス」案は

37. **ヌルデリミタのグリフ ╎ ┆(ユーザー裁定 2026-07)** — `\left.`/

38. **\op の名前ボックス(ユーザー裁定 2026-07)** — `\op`/`\op*` は
    その場(カーソル位置)に入力ボックスを開く。表示は選択と同じ背景
    ボックス+立体ラン(表示専用の Func 原子: 引用符は出さない、
    スペースは ␣ 表示)。英数+スペースが名前に入り、Enter/Tab で確定、
    Esc で取消、それ以外のキーは確定してから通常動作(「外に出たら
    確定」)。確定規則: スペースで単語に分割し、各単語は辞書語なら
    Func、それ以外は Text{math}(=裸の立体ラン、引用符なし)。
    `\op` は単語を ␣ で繋いで挿入、`\op*` は単語をバンドの piece に
    して(`ess sup` → `┈ess┈sup┈`)下極限へ入る — argmax 亜種の
    その場定義がこれで済むため、Field::OpBase(基底の自由編集)は
    不採用。再編集は消して打ち直し(Text 原子性と一貫)。引数密着
    スタイル `\opvol`/`\op*esssup` は廃止(\rm/\text は引数式を維持)。
    LaTeX は Text を含む複数 piece 基底を \operatorname*{ess sup} に
    合流、Typst は op("ess sup", limits: #true)。

42. **大型山括弧は罫線のみ(ユーザー裁定 2026-07)** — Unicode の ⟨ と
    罫線 ╱╲ を混ぜると角度が合わずに折れて見える(「頂点がめり込む」)
    ため、複数行の山括弧は**対角線 ╱╲ だけ**で描く。⟨ ⟩ は1行のときだけ。
    高さは常に偶数(腕が対称)で、折り返しは**同一列の縦ペア**
    (左=╱の直下に╲、右=╲の直下に╱)、ペアの上側の行が基線という規約。
    この形は基線上の全行にグリフがあり(cases 格子縁案で撤回した
    「基線上不可視」問題を踏まない)、しかも折り返しペアが局所判定
    できるので、従来の共有グリフ列ウォークより側の解決が単純。
    腕の側解決は対角線を折り返しまで辿る方式だが、**隣接する山括弧の
    腕は1本の対角線に融合する**(fuzz発見)ため、走査の各ステップで
    折り返し判定を行う。デリミタ描画は「範囲へ先にパディング→ mid を
    全高で描画→柱/三角で包む」構造に再編。旧1列形式(╱⟨╲)は入力
    として受理し fmt が移行する。

45. **ドット入りローマンラン・\rm/\text ボックス・rcases(2026-07)** —
    `i.i.d.` が `'i'.'i'.'d'.` に砕ける問題(dx と同根: ドットがランを
    切る)への対応。字句規則を拡張し、内部の `.` は直後が英字のとき、
    末尾の `.` はラン内に既に `.` があるときだけランに参加
    (`sin.` は Func+ピリオドのまま、辞書はドット入りランを引かない)。
    描画は同じ規則を満たす Text を裸で出し、満たさなければ引用
    ('x..y' — 引用の中身charset に `.` を追加)。分離義務を2つ追加:
    「`.`+英字」(exp.i.i.d. への吸収防止— fuzz 発見)と
    「ドット入りラン+英字/`.`」。prime の隔離集合にも `.` を追加。
    \rm / \text は単体で \op 同様のその場ボックスに(\rm は英数+`.`、
    \text は引用符以外の自由文字+スペース)。直結形 `\rm<x>` は存続し
    charset に `.` を追加。`\rcases`(mathtools、左ヌル+右ブレース)を
    グリッド表に追加 — 描画・パースは既存機構がそのまま対応し、
    LaTeX env と Typst cases(reverse: #true) の対応だけ足した。

46. **\text の実スペース・KaTeX 関数辞書・ceil/floor/norm(2026-07)** —
    (a) `"…"` は引用符が範囲を区切るので中身は実スペースのまま
    (`'…'` は走査が空白で止まるため ␣ を維持)。
    (b) 関数辞書を KaTeX の演算子一式+宣言系(asin, Tr, rank, erf,
    Res, PV, Re, Im, grad, curl…)に拡張。LaTeX 出力は LATEX_FUNCS に
    ある名前だけ \name、他は \operatorname{name}(\Re は ℜ になって
    しまう等のため)。Typst も TYPST_FUNCS 外は op("…")。
    plim/injlim/projlim は LIMIT_FUNCS 入り。var* 系(上下線付き lim)は
    複数文字アクセントと合わせて再検討(ロードマップ)。\div は
    ÷ と衝突するためユーザー判断で見送り。
    (c) デリミタ追加: ⌈⌉⌊⌋ と ‖(ノルム)。**1行は Unicode グリフ、
    複数行はブラケット片を片角だけ使う**(3案目・ユーザー最終指定):
    ceil = ⎡+⎢(足なし)、floor = ⎢+⎣(頭なし)、両角あり = ブラケット。
    太さも接続もブラケットと完全一致する。⎡⎢⎣ が3家系共有になるため、
    家系解決を「連続列ランを走査し、含まれる角の組で決める」方式に
    一本化(open_spec_at — ┠ ジャンクションも同じ走査で解決し、
    従来の1グリフずつのウォークを置換)。経緯: 1案目 ⌈+⎢ は
    グリフがつながらない、2案目の太罫線 ┏┓┗┛+┃ は太さが浮く
    (いずれもユーザー指摘)。ノルムは 1行 ‖・複数行 ║(罫線)。
    ‖/║ は左右同一グリフのため側を行内パリティで解決 — **ノルム直下の
    ノルム入れ子は原理的に曖昧で非対応**(文書化+ジェネレータは内側を
    ⎸⎹ に書き換え)。LaTeX \left\| / Vmatrix、Typst norm() /
    mat(delim: "||")。

47. **複数文字アクセント(ユーザー提案 2026-07: 既存バンドの使い回し、
    2形態を経て確定)** — `WideAccent{over, under, base}`。
    1案目は「基底をバンドで挟み、極限領域にマークを置く」(仕様増分
    最小: マークのみの極限行は元々エラー=空き構文)。ユーザーの
    「基線は裸のままが見た目が良い。┈ は複数行区切りで既に文脈依存」
    という裁定で**マーク側バンド**に反転: 基底は裸、`┈┈^┈┈` の
    範囲行が上下に密着(brace ╭──╮ の実装パターンを鏡写し:
    範囲行は基底+2で1列はみ出し、パーサは空白基線列から見上げて発見、
    基線復元は範囲行を飛ばして反対側へ潜る)。この反転の副産物で
    **基底の平坦制約が消えた**(基底は任意ブロック — \overline{分数}
    可。バンドの piece ではなく範囲の下の領域になったため)。
    基底はカーソル非対応(選択を包む、re-edit は消して作り直し)。
    基底1文字+単マークは Accent に正規化。fuzz が4件発見:
    (a) 空白領域を極限と誤認 → 内容有無とマーク純度を分離;
    (b) プライム基底の Accent をパースが読めない → プライム arm に
    アクセントスタック追加; (c) 全面打ち消しの正準方向 → brace と同じ
    「外側 Cancel」に統一; (d) バンドがデリミタ列や背の高い隣と密着して
    走査が食う → 自己終端スキャナ+WideAccent 両側の分離空白義務。
    var* 系 lim(マークと極限の同時装着)は引き続き非対応。

48. **伸縮マークの充填(ユーザー要望 2026-07)** — wide アクセントの
    マークの当時の形: vec は `─` 胴体+ASCII の `>` 頭(`┈──>┈`。当初は
    普通の `→` 頭だったが「罫線と → が微妙に繋がらないフォントがある」
    ため \xrightarrow と同じ `>` に。バンド行は予約文脈で原子が住めない
    ため衝突しない — コンパクト形は従来どおり原子と互いに素な ⇀)、
    hat/check は最終的に中央1文字の `˰` / `˯`(`╱─…─╲` 伸長 →
    「┈╱╲┈」固定幅ペア → ˰ 導入後にユーザー裁定で低位矢頭1文字に
    収束。旧形式の斜めペアも寛容に読む)、
    overline は `_` 充填(¯ はセル上部に浮くのでユーザー指摘で `_` に —
    √ のオーバーラインと同じ「基底密着」の理屈。AST のマークは ¯ の
    まま)、underline は逆に `¯` 充填(下から基底に密着。AST は ‗)、
    tilde は繰り返し、点系は中央1文字のまま。`┈¯¯┈` が上下どちらの
    バンドかは位置(基線の上か下か)で決まるので、¯ の繰り返しを
    over 分類から外して一意化した。
    バンド走査は「先頭┈→素材→末尾┈」の段階機械にし、末尾 ┈ の後に
    現れる素材文字を吸収しない(fuzz 発見: 祖先ブロックが密に切り出す
    と兄弟の上付き ^ がバンド行に密着し、旧貪欲走査が食っていた)。
    **コンパクト形(1文字)も低位変種のあるマークは同じ扱いに揃えた**
    (ユーザー提案): 上バーは `_`、hat は `˰` U+02F0、tilde は `˷`
    U+02F7(wide のバンド充填も `˷`)、check は `˯` U+02EF、ring は
    `˳` U+02F3(wide の中央1文字も `˳`)、下バーは `¯` で描く(AST
    マークは ^/ˇ/˜/¯/˚/‗ のまま、浮いた旧グリフも寛容に読む。パースは
    描画グリフ→マークの写像を accent_stacks と基線復元のマーク
    剥がしに入れるだけ)。dot は当初 `.` の流用を検討したが
    (原子と衝突し `ẋ^{.}` vs `ẍ` の曖昧性が生じる)、ユーザー提案の
    ONE DOT LEADER `․` U+2024 で解決 — 予約字なので原子と互いに素の
    まま(§6 不変条件を維持)。ddot は `․․` を**基底の右に1列はみ出す**
    形(ユーザー要望): ブロックを幅2にしてはみ出し列の基線を空白で
    持ち、パースは「真上 `․` +右隣 `․` +その列に他の内容なし」で
    対にする(隣の原子の dot は基線が埋まるので誤食しない)。fuzz
    発見: 1文字 \mathrm の裸/引用判定(glue)がノード隣接で見て
    いたため、ddot の空白はみ出し列が物理隣接を切って裸の `e` が
    変数に化けた — glue 判定を辺ごとにし、ddot の右辺は glue しない。
    コンパクト vec は ⇀ の代わりに半角矢印 `￫` U+FFEB で描く
    (ユーザー提案 — wide の `──>` と見た目が揃う。原子の → とは
    別字なので互いに素性は保たれ、AST マークは ⇀ のまま)。
    breve(˘)は低位変種が Unicode になく唯一浮いたままだったが、
    使う機会も乏しいためユーザー裁定で**削除**。空いた浮き `˜` は
    **utilde の描画グリフ**に転用(ユーザー要望): AST マークは
    over `˜` / under `˷` の対で、描画グリフは互いに入れ替わる
    (over は低い `˷`、under は高い `˜` — どちらも基底密着)。wide の
    下バンドは `┈˜˜˜┈`。充填グリフは片側専用(`˷`=上、`˜`=下)に
    排他化した — 両側に読めると基線復元の潜り方向(上バンドなら下へ、
    下バンドなら上へ)が誤り、fuzz が「下バンドを旧 `˜` 繰り返しの
    上バンドと誤読して空領域に潜る」ケースを検出した。Typst には
    under-tilde アクセントがないため `attach(x, b: sym.tilde)` で出力。fuzz 発見: √ の貪欲な `_` オーバー
    ラインと隣のバーの `_` が同じ行で融合して根号が隣を食う —
    兄弟境界で `_` 同士が物理接触する場合に分離空白1を挟む幾何規則を
    render の結合部に追加(貪欲な `_` 走査は √ だけなので、これで
    このグリフの衝突は尽きる)。
    もう1つの fuzz 発見: hat バンドを縦に重ねると外側の `╱` の真下に
    内側の `╲` が来ることがあり、山括弧の折り返し(同一列の縦ペア)に
    見えてしまう。hat の `╱` は必ず右隣が相棒の `╲`(close 側は左隣が
    `╱`)なので、折り返し判定に「右隣≠╲ / 左隣≠╱」のガードを追加
    (本物の折り返しの内側がその位置に斜線を持つことはない。ただし
    `╱┈∫┈╲` のようにバンドは折り返しに密着できるので ┈ は除外しない)。

52. **prime=′・立体ラン=operatorname・依存整理(ユーザー要望 2026-07)**
    — (a) `'` は**常に \mathrm 引用の区切り**にし、prime は独立した原子
    `′` U+2032(`'` キーが挿入する)。prime と引用の共用をやめたことで

    開き、閉じ `"` で確定・`\"` `\\` でエスケープ(括弧類は不可 —
    引用は不透明なので括弧の深さ計数が狂う)。(c) 立体ランは
    **2文字以上=\operatorname / 1文字=\mathrm**(AST は Text{math} の
    ままで長さから決まる。複数文字 \mathrm が要るときは `'f' 'o' 'o'`)。
    (d) マイナスは ASCII `-` のまま(U+2212 への置換を廃止 — ASCII 版の
    別扱いが無くなったので区別が不要)。(e) アクセントの寛容入力(AST
    マーク文字を直接置く形)を廃止し、予約グリフは描画形だけに。
    (f) `\`+Space = `\space`。(g) ^B 中の Shift+矢印はモードを抜けて
    通常の範囲選択へ。(h) 依存整理: clap を外して手書きの3サブコマンド
    パーサに戻し、session/`.tex` 保存(と ␠ スペーサ綴り)を削除、
    クリップボードは **arboard**(crossterm 0.29 の OSC52 も試したが
    ratatui が 0.28 を束ねるため二重依存になり不採用)。
    (i) 長い数式の**横スクロール**(カーソル/フリーカーソル追従、

53. **Typst 出力の廃止(ユーザー裁定 2026-07)** — 出力を LaTeX 一本に
    絞った。二重メンテの実害が大きい割に得るものが薄かった: 記号表は
    `FuncSpec`/`WordOp` に LaTeX と Typst の2フラグを持ち、
    シリアライザは `Node` ごとに2実装、テストもコーパス全件で2系統を
    検証していた。AA→AST の可逆性という中核の価値は変換先の数とは
    独立なので、必要になれば `output/` に別モジュールとして戻せる
    (AST は変換先中立のまま)。

54. **AST の再編: Typst 廃止・立体ランの一本化・単一ピースバンド
    (ユーザーとの設計対話 2026-07)** — 出発点は「Typst をやめて実装を
    単純にしたい」+ AST への疑問5点。詰めた結果、次の連鎖が見えた。
    (a) **LaTeX は常に `\operatorname`**(`\sin` を使わない)。
    `\sin` と `\operatorname{sin}` は同じ組版になるので、辞書語か
    否かで出力を変える意味がない。これで `FuncSpec.latex` /
    `WordOp.latex` の2フラグ、`\mathop{…}` グループ化、`op_words` の
    `has_text` 分岐が**まとめて消えた**。多語名の見た目は
    `FuncSpec.spaced`(`argmax` → `arg\,max`)だけで足りる。
    (b) **`Text{t, math}` を解体**して `Func(String)`(立体ラン、2文字
    以上)/ `Roman(char)`(立体1文字 = 微分の d)/ `Text(String)`
    (`\text`)へ。`Func` と多文字 `Text{math:true}` は**同じ絵**になり、
    差は「辞書語か」= 文字列から導出可能な冗長性だった。`Func` は
    辞書縛りをやめ「任意の立体名」に。辞書の役目は limits 判定と
    ASCII ランの字句解析だけになる。
    (c) **バンドは1ピース**に。諸悪の根源は `┈arg┈max┈` の空白で、
    裸に戻すと "arg max" が2ノードに割れるため BigOp→Func が1対1に
    ならず、「畳めるのは辞書に載った単独基底だけ」という条件付き規則が
    必要だった。空白を諦めて `┈argmax┈` にすると1対1になり、
    **極限が空なら常に裸へ**という無条件規則になる(`promotable_base`
    が不要に)。LaTeX 側だけ `arg\,max` と綴るので見た目は損なわない。
    (d) **`BigOpSym{op}` / `BigOp{name}` に分割**。ノードを割る動機は
    「記号か文字列か」ではなく、基底が `Row` だと `BigOp{base:[Frac]}`
    のような無意味な木が型で作れてしまう点。畳み込み規則は両者で対称に
    なった。
    (e) UI は不変: `\lim` は今までどおりバンドで実体化して下極限に
    カーソルが入り、抜けると裸になる。エディタは自分の木にバンドを
    保持したまま描画だけ切り替えているので、「編集中は覚えていて、
    保存時は忘れる」は既に成立していた。
    ついでに fuzz が**既存バグ**を1件出した: `Cancel` に包まれた
    WideAccent は `Info.wide_accent` が立たず分離空白が入らないため、
    隣のバンドと密着して走査が食い合っていた(`has_wide_accent` が
    ラッパを透過するよう修正)。

55. **原子の許可リスト化と LaTeX 綴りの全域化(2026-07)** —
    `is_reserved_glyph` は `symbol_by_name` のフィルタにしか使われて
    おらず、**パーサは任意の文字を `Sym` にしていた**(実質 deny-list)。
    穴は2方向に開いていた: レイアウトは1セル1文字のグリッドなので
    全角文字や絵文字が1つ混ざると全カラムがずれる。そして表に無い
    文字は LaTeX の綴りも持たない。`symbols::is_atom` を**表から導出**
    される許可リストにし(手書きしない)、パーサとキー入力の両方を
    通した。受理集合の**全メンバーが1セル幅・非結合**であることを
    テストが全走査で保証する — レイアウトが依拠する性質なので信頼せず
    検査する。
    ASCII を締めた結果、**壊れた LaTeX を出していた4文字**が判明:
    `^`(上付き構文)・`~`・`` ` ``・`\`。原子から外した(正しい綴りは
    `\sim` `\backslash` 等)。`# $ % &` は原子のままシリアライザで
    エスケープ — 生の `%` は以降を全部コメントアウトしていた。
    逆引きは、スタイル族が**規則で綴れる**(`𝔸`→`\mathbb{A}`、
    unicode-math 名)ので 846 件中 672 件が一気に埋まり、残りは
    121 件。上下付き修飾文字(`\supA`→ᴬ)は原子から削除 —
    `\^A` が構造的な上付きを作るので代替があり、「上付きは構造で
    持つ」方針とも揃う。残る 121 件は生 Unicode 出力(unicode-math
    前提は既存の方針)だが、**テストが件数を固定**するので黙って
    広がらない。

56. **WideAccent の重ね掛け(ユーザー指摘 2026-07)** — コンパクトな
    `Accent` はマークをリストで縦に積めるのに、`WideAccent` は
    `over: Option<char>` で1つしか持てず、重ねるには入れ子にするしか
    なかった。これは一貫性を欠くだけでなく、同じ絵に2つの AST
    (重ねと入れ子)が対応しうる。`overs`/`unders` の `Vec<char>` に
    揃え、描画はバンド行を積むだけ(幅は変わらないので絵は一意)、
    パースは基線から離れる向きにバンドが続く限り読む。
    実装中の fuzz で**走査方向の取り違え**を検出: `wide_accent_at` は
    上から探すので最も外側のバンドを返すが、そこから外向きに歩いて
    いたため1枚しか拾えず、残りが入れ子として読まれていた(内向きに
    歩いて反転する形に修正)。
    ついでに LaTeX の入れ子順を `Accent` と統一(下マークを内側)—
    以前は WideAccent だけ上マークが内側で、両者が食い違っていた。

57. **表の役割整理(2026-07、当初案の撤回を含む)** — 検討の出発点は
    「`SYMBOLS` 103件のうち84件が ext と重複、うち4件は黙って上書き」
    という重複の指摘で、当初は「役割で2表に分割」を提案した。しかし
    測り直すと**あの重複は冗長ではなくピン留め**だった: 分割しても
    char→名前の逆引きに ext と同じ対が要るので重複は消えず、逆に
    「ext から導出」に寄せると**再生成のたびに `\to` の意味が変わり
    うる**という悪化を招く。4件の食い違いはピンが実際に働いている
    証拠だった。よって表は分けず、
    (a) `SYMBOLS` のドキュメントを「ピン留めの表」と明示し、
    (b) 意図的な上書きを `INTENTIONAL_OVERRIDES` として列挙、
    (c) **未文書の食い違いが増えたらテストが落ちる**ようにした
    (暗黙の優先順位という本当の問題だけを潰す)。
    `resolve(cmd)` への集約は見送り: `command_known` の clone-probe は
    実体の `execute` を走らせるので**構造的にドリフトしない**のに対し、
    並行する `resolve` を手で維持すると逆にドリフト源になる。
    代わりにエイリアスを `symbols::ALIASES` に集約し(`\sqrt3`=`\cbrt`、
    `\limits`=`\op*`、`\xrightarrow`=`\xto` …)、dispatch は各コマンドを
    1回だけ名指すようにした。全エイリアスが対象と同一結果になることは
    テストが総当たりで確認する。
    `Accent{base: char}` の `Sym | Roman` 化は**不可能**と判明: 立体
    1文字の正準形は引用付き `'d'` で、そこにマークを載せる絵の規則が
    無く、裸の `d` は斜体変数に読み戻る。型を広げると**描いても
    パースで戻らない AST** が作れてしまい、中核の契約に反する
    (base は常に Sym の原子であることをテストで固定した)。

58. **テーブルの集約とファイル分割(2026-07)** — 「必要なテーブル」の

    (a) **括弧**が最大の分散で、同じ知識が8箇所(仕様文字リスト・

60. **原子表を char キーに(ユーザー提案 2026-07)** — 「α を α 自身を
    入力するコマンドとみなし、`\al` `\alpha` はそのエイリアス、LaTeX
    出力用の綴りは別管理」という提案を採用。実測が提案を裏付けた:
    ext には既に `al`/`alp`/`alpha`→α が並んでいて**入力名は事実上
    エイリアス**だし、名前キーの `SYMBOLS` は5文字に2名ずつ持っており
    (`le`/`leq`、`to`/`rightarrow`…)**どちらを LaTeX に出すかが表の
    並び順という暗黙**で決まっていた。
    `AtomSpec { ch, latex, also }`(103名→98行)に組み替え:
    - `ch` が正準の同一性(文字そのものがコマンド)
    - `latex` が**唯一の出力綴り**(≤ は常に `\le`)— 暗黙だった選択が
      フィールドになった
    - `also` が追加の入力綴り(`\leq` でも打てる)
    入力解決は「curated の綴り(latex∪also)→ スタイル族 → ext」の
    まま。コマンド側の `ALIASES`(`\sqrt3`=`\cbrt`)と対になる形で、
    「**入力綴りはすべて正準物へのエイリアス**(記号なら文字、
    コマンドなら正準名)、出力綴りは別テーブル」という一貫した
    モデルになった。行の正準性(char 一意・綴り一意・出力=latex)は
    テストで固定。

61. **Edit enum — 綴り解決と適用の分離(ユーザー提案 2026-07)** —
    「frac 挿入などの操作を Action/Edit として enum 化し、入力(キー・
    コマンド)→Edit のテーブルで管理、一部は AtomSpec から自動導出」
    という提案を実装。§57 で `resolve(cmd)` 集約を「execute と並行維持
    するとドリフトする」と見送ったが、resolve+apply が execute を
    **置き換える**なら並行物が存在せず、反対理由が消える。
    - `Edit` は6種+格子操作: `Insert{node, wrap}`(構造テンプレ)・
      `Sym`・`Accent`・`Delim`・`Grid`・`Mid`・`AddRow`系・`OpenBox`。
      27分岐の大半が `Insert(Node)` に畳めた — apply の一般規則
      「選択は最初のフィールドへ、次の空スロットに入る(無ければ通過)」
      が frac(選択→分子、カーソル→分母)も sqrt も brace も再現する。
    - `resolve` は**純粋関数**: エイリアス1ホップ → 構造名 → 格子/\lr
      解析 → FUNCS → ACCENTS → スクリプト → ATOMS(kind が Sym/band を
      決める = **AtomSpec からの自動導出**)→ \rm/\text 接尾形。
    - `command_known` の **clone-probe ハックが消えた**
      (`resolve(cmd).is_some()`)。リアルタイムプレビュー(ロードマップ)
      は resolve が返す `Insert(node)` を描くだけになった。
    - AtomSpec は `{ch, latex, kind}` に確定し、`also` は廃止して
      記号綴り(`\leq`→`\le`)を **`ALIASES` に統合**(コマンド綴りと
      同じ1ホップ規則、`symbol_by_name` の内側で解決)。`BIG_OPS` は
      kind に吸収されて表ごと消滅、execute にあった bigop の重複分岐も
      消えた。
    - **モード切替は Edit に入れない**: 境界は「undo 対象の木の変異か」。
      ^F/^G/^B・移動は Key→Effect 層に残る(`OpenBox` だけは
      「確定すると木を変える操作の開始」として Edit 側)。
    - 移行が**潜伏パニックを1つ暴いた**: Norm ノード導入時、
      `field`/`field_mut` への Seg(0) アーム追加が置換ミスで静かに
      失敗しており、`\norm` 内に文字を打つと落ちる状態だった
      (apply の空スロット判定が先に踏んで発覚。回帰テスト追加)。
    キー側の Edit 合流(`(` や `^` を `apply(Edit)` 経由に)は次の一手。

62. **Arrow / Accent の enum 化(ユーザー指示 2026-07)** — Radical と
