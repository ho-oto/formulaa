# mascii の AA はこう読まれる(パースのメンタルモデル)

厳密な定義より「絵を見たときにパーサが何を考えるか」を優先した文書。
細部の正確な規則は docs/aa-spec.md、設計の経緯は docs/design.md。

## 大前提

- AA は**ソースコード**。パーサは受理する全ての絵を一意に読み、
  `fmt` がそれを整った正準形に直す。手書きの揺れ(ASCII 文字、余分な
  空白、旧形式)は広く受け付ける。
- **空白は「有る/無い」だけが意味を持つ**。2個と3個で意味が変わる規則は
  存在しない。空白の役割はトークンを切ること(貪欲に読む構造は空白で
  止まる)。
- 打ち消し(U+0338)は文字の後ろに付く結合文字なので、読み込み時に
  「そのセルに斜線フラグ」という形で分離しておく。

## 手順0.5: まず行に分ける(複数行数式)

**唯一のグリフが `┈` 1文字の行**は数式の行区切り(バンドの `┈` は必ず
名前を密着で挟むので、1つの数式の中に単体の `┈` だけの行は現れない)。
区切り行で絵をセグメントに分割し、各セグメントを独立した数式として
以下の手順(基線推定から)で読み、`Break` で連結する。区切りに接する
全空白行は整形扱いで捨てる。区切り行なしで全空白行が数式を分断して
いたらエラー。区切り行の間に何もなければ空行。

## 手順1: 領域の基線を決める

パースの単位は「矩形領域+基線行」。基線が親から分かっていない領域
(分数の分子など)は、**トリム後の左端列**の形で決める:

```
   1          ∞                        ⎛   ⎞      ┌   ┐
 ─────      ┈┈∑┈┈       𝑥̂          ⎜ … ⎟        …
  𝑥+1        𝑛=1        ↑最上段のマーク ⎝   ⎠      └   ┘
 ↑─の行     ↑┈の行       を剥いだ残り   ↑中身で再帰  ↑extent中央
```

- 左端列に `─` `┈` `═` があればその行(範囲行は中身より左に出っ張る)。
- アクセントマークなら上下から剥いで、残った基底の行。
- 左端列に `╱` とその直下の `╲` があれば山括弧の折り返し: `╱` の行が基線。
- 縦括弧なら: 波・山括弧は**頂点(⎨ ⟨)の行**をそのまま読む。丸・角括弧や
  `⎢ ┆` は中身に潜って決める(中身が行列なら extent 中央)。
- 格子の縁(`┌ ├ └`)なら extent 中央行。
- `╭` なら下側(引数側)に、`╰` なら上側に潜る。
- どれでもなく非空白行が1つだけならその行。決まらなければ曖昧エラー
  (基線の分かる書き方に直してもらう)。

## 手順2: 基線を左から右へ読む

基線行を走査し、見えた形で分岐する。各構造は自分の列範囲を消費し、
その範囲の上下の矩形へ再帰する。以下「この形を見たら、こう」の一覧。

### 斜線フラグが立っている → 打ち消し

```
 𝑥̸𝑦̸
────  ← ではなく、基線上の 𝑥̸𝑦̸ のような flagged セルのラン
```

フラグ付きセルのランが `\cancel`。途中に空白があっても、その区間が
**全て空白か打ち消し済み**なら1つの打ち消しとして繋がる(最大打ち消し)。
中身は打ち消しモードで普通に再帰する。

### 空白が続く → 直前要素の添え字たち

```
 2      𝑏
𝑥  𝑦   𝑎   ← 基線が空白の列範囲。上にあるものは上付き、下は下付き
        𝑐
```

基線が空白のランは、上側・下側を**別々に**塊へ分割して `^`/`_` にする。
両側とも空白の列は塊の内部(区切りではない)。括弧などの内側は
保護されていて、そこで塊が切れることはない。

ただしランに入る前に2つだけ先読みする:

- ランの中の列に格子の縁 `┌ ├ └` があり、その格子の**中央がこの基線**なら、
  添え字ではなくインラインの裸行列(下記)として切り出す。
- ランの中の列の上に `╭`(下に `╰`)があり、その範囲行の**引数側がこの
  基線を含む**なら overbrace / underbrace として切り出す。

どちらも「基線がその構造の空白部分を通る」せいで走査が素通りしてしまう
形なので、列に必ず現れる予約グリフを目印に拾う。

### `───` → 分数。ただし `──>` は矢印

```
 𝑎+𝑏         𝑓
─────       ──>      ─── >
  2        ↑矢印     ↑分数と原子の >(空白で切る)
```

`─` のランを読み、**直後に `>` が密着していれば**ラベル付き矢印
(上下は over/under ラベル)、そうでなければ分数(上下は分子/分母)。
`═══>` は二重矢印 `⇒`。`<──` `<══` は左向き(`<` の直後が胴体かを
1文字先読み)。密着か空白かだけで決まる。

### `┈` に挟まれた列 → 上下極限つきのバンド

```
  ∞
┈┈∑┈┈ 𝑎ₙ     ┈lim┈ 𝑓(𝑥)     ┈argmax┈ 𝑓(𝑥)
 𝑛=1          𝑥→0              𝑥∈𝑆
```

**空白なしで `┈` に挟まれたものは何であれ**バンド=上下に極限を取る。
別枠として、**基線の上下に浮いた「┈+マーク素材だけの行」**は伸縮
アクセントの範囲行(`\widehat{abc}`)。素材は `┈┈˰┈┈`(hat。
旧 `╱╲` ペアも読む)`┈┈￫┈┈`(vec)`┈___┈`(overline)
`┈˷˷˷┈`(tilde 低位形の繰り返し)、
下側は `┈¯¯¯┈`(underline)`┈˜˜˜┈`(utilde)など(点系は中央の `․` `․․` `˳` 等。充填グリフは片側専用: `˷` は上・`˜` は下)。brace と同じく1列はみ出すので、
走査は基線の空白列から見上げ(下ろし)て発見し、範囲行は基線に
ならない(基線復元は反対側へ潜る)。
中身は**1ピース**(空白のない1つのラン)。1文字で ∑ 系なら記号バンド、
それ以外は名前つきバンド。
バンドは空白まで貪欲に読むので、隣の要素とは必ず空白1で切れている。
極限が両方空のバンドは**常に**裸の形に正規化される: `┈∑┈` は原子 `∑`、
`┈lim┈` は立体ラン `lim`。名前が1ピースなので裸の絵はちょうど1つの
ノードに読み戻り、両向きが1対1で対応する。

### 縦に伸びた括弧 → デリミタ

```
⎛    1 ⎞     ⎧ 1 ⎫      ╱    1 ╲     ⎢𝑥⎥     ┆…┊
⎜1 + ─ ⎟     ⎨───⎬     ╱ 𝑥+─── ╲    ↑絶対値  ↑ヌル(\left.相当)
⎝    𝑥 ⎠     ⎩ 2 ⎭     ╲    2  ╱
                        ╲     ╱
```

読み方は全族共通:

1. 開き列(`(⎛⎜⎝` `[⎡⎢⎣` `{⎨` `⟨` `⎢` `┆` のどれか)を見つけたら、
   角のない `⎢⎥` 延長片の列は縦棒(\abs)と読み、
   基線行を右へ深さ計数して**構造的に対応する閉じ列**を探す。
   左右のグリフは必ず別文字なので、`(0,1]` のような不一致ペアも数えられる。
   両側で同じ文字になる `⎪ ╱ ╲` だけは、その列を縦に辿ってどちら側かを
   確かめる。
2. 内側に**全高の `│` 列**があれば middle: `⟨ψ│H│ψ⟩` `{𝑥│𝑥>0}` のように
   セグメントへ分割する(各セグメントは親と同じ基線)。
3. 波括弧の頂点 `⎨` は必ず基線行に描かれる。山括弧(複数行)は罫線の
   腕だけで描かれ、折り返しが**同一列の縦ペア**(左=`╱` の直下に `╲`、
   右=`╲` の直下に `╱`)になる — ペアの上側の行が基線。腕のグリフが
   どちらの括弧のものかは、対角線を折り返しまで辿れば決まる(隣接する
   括弧同士で腕が1本の対角線に繋がることがあるため、辿りながら各セルで
   折り返し判定をする)。1行のときだけ `⟨ ⟩`。
   なお hat バンドが `╱╲` ペアだった旧設計では、縦に重ねると `╱` の直下に
   別バンドの `╲` が来ることがあるが、hat の `╱` は必ず右隣が相棒の
   `╲`(close 側は左隣が `╱`)なので折り返しとは区別できる — 本物の
   折り返しの内側がその位置に `╲`/`╱` を持つことはない。

### 行列 — デリミタの中の最小マーカー、裸なら格子

```
⎡ 𝑎   𝑏 ⎤      ⎡   ┬   ⎤      ⎛ 𝑎 ⎞      ┌   ┬   ┐
⎢   ┼   ⎥      ⎢ 𝑎   𝑏 ⎥      ├   ┤        𝑎   𝑏
⎣ 𝑐   𝑑 ⎦      ⎣   ┴   ⎦      ⎝ 𝑏 ⎠      ├   ┼   ┤
 ↑複数×複数      ↑1行           ↑1列         𝑐   𝑑
                                          └   ┴   ┘ ↑裸(\array)
```

デリミタの中に「**空白と `┼` だけの行**」「上端行の `┬`/下端行の `┴`」
「デリミタ列に食い込んだ `├ ┤`」のどれかが見えたら、中身は1つの行列。
マーカーの位置で行と列を切り、各セルで基線を測り直す。接合の `├ ┤` は
格子の縁と同じ字だが、「同じ列に ⎛/⎡ 系のグリフが続く」ことで区別する
(裸格子の縁はマーカー間が空白)。
波括弧は融合しない(頂点 `⎨` と両立するジャンクションがない)ので、
`{ }` の中の行列は裸格子のまま包まれる。波括弧の列は最低高さ3
(2行の中身でも ⎧⎨⎩ の3行が包む)。
「マーカー以外が混ざった行」は区切り行とみなさない — 入れ子の行列は
必ず自分の括弧や縁のグリフを同じ行に落とすので、誤検出しない。

裸の行列(括弧なし、\begin{matrix} 相当)は自分で範囲を示す必要が
あるため、外周含む全交点に `┌┬┐ ├┼┤ └┴┘` を置いたフルフレームの格子。
角があるので、隣り合う2つの格子が1つに融合して読まれることはない。

セルの中身やまわりの空白は何桁あっても意味を持たない(境界は常に
マーカーが決める)。

### `╭──╮` / `╰──╯` → overbrace / underbrace

```
  𝑛
╭───╮
 𝑎+𝑏 + 𝑐     ← \overbrace{a+b}^{n} + \underbrace{c}_{m}
      ╰─╯
       𝑚
```

範囲行が引数ブロックに密着し、その先にラベル。分数の罫線を基線の外へ
ずらした形だと思えばよい(幅の規則も分数と同じ)。

### `"…"` と `'…'` → テキスト(`'` は常に区切り、prime は ′)

```
∫𝑓(𝑥)dx      "if x"      'd'𝑥        𝑥′′
     ↑裸のラン ↑\text      ↑1文字\mathrm  ↑prime 原子 ′ ×2
```

- `"…"` は常に `\text`(実空白をそのまま入れられる)。
- `'` は**常に** `\mathrm` 引用の区切り: 閉じ `'` が(空白を跨がず)あり
  中身が非空の ASCII 英数/`␣`/`.` であること。閉じが無ければエラー。
  prime は独立した原子 `′` U+2032 なので衝突しない。
- `"…"` の中では `\` が次の1文字をエスケープする(`\"` `\\`)。

### ASCII 英字のラン → 関数か、ローマン体か、変数

ランごと(空白・記号・イタリック文字で切れる極大列)に:

| 見た目 | 読み |
|---|---|
| `sin`(辞書語そのもの) | `\sin` |
| `asiny` `dx`(2文字以上) | `Func` → `\operatorname{asiny}` |
| `a`(単独の1文字) | イタリック変数 𝑎 |
| `d𝑦`(1文字だが文字に密着) | `Roman('d')` → `\mathrm{d}𝑦`(正準出力も裸。引用符は文脈で自動着脱) |

ラン内の部分マッチはしない(`sinx` は \operatorname{sinx}。sin x は
`sin x` か `sin𝑥` と書く)。正準形の変数はイタリック体コードポイント
なので、この規則は手書き ASCII のためのもの。

### `√ ∛ ∜` → 累乗根

```
┌────
√𝑥+12      ← `┌` +オーバーライン `─` の右端が中身の右端。茎 │ は中身の全行
```

### 原子と、その真上/真下 → アクセント

```
^
⇀     ← マークは縦に重なってよい(内側から外側へ)。\hat{\vec{a}}
𝑎
```

原子の真上・真下のセルは他の何にも使われないので、マークが続く限り
縦に読むだけでよい。低位の変種を持つマークは基底に密着して描かれる —
真上の `_` は上バー(AST マーク `¯`)、`˰` は hat(`^`)、`˷` は
tilde(`˜`)、`˯` は check(`ˇ`)、`˳` は ring(`˚`)、`․` U+2024 は
dot(`˙`。原子の `.` とは別字)、`￫` U+FFEB は vec(`⇀`。原子の
`→` とは別字)、真下の `¯` は下バー(AST `‗`)、
真下の `˜` は under tilde(AST `˷` — チルダは AST と描画が上下で
入れ替わる対)として読む(浮いた旧グリフ `¯ ˜ ^ ˇ ˚ ˙`/`‗` も
そのまま置く旧形式は廃止 — AA に現れるのは密着形のみ)。
ddot は `․․` が右に1列はみ出す形: 真上が `․` で右隣も `․`、かつ
その列に他の内容がないときだけ対として読み、はみ出し列を消費する
(隣の原子自身の dot は基線が埋まっているので対にならない)。√ のオーバーライン
`_` とバーの `_` が同じ行で隣接すると融合しうるため、正準形では
間に分離空白が入る。

### その他

- `⬚` は読み飛ばす(空スロットの表示と、基線の目印)。
- `𝑥² 𝑎ᵢ` のインライン上付き/下付き文字はそのまま `^`/`_`。
- 対応の取れていない閉じ括弧 `) ] } ⟩` はエラー(原子の閉じ括弧は
  左右不一致ペアの深さ計数と衝突して読みをずらすため、存在できない)。
- 基線上のトークン(原子・英字ラン・引用・インライン添え字)の真上と
  真下は、消費されたアクセントマークを除いて**空白でなければならない**。
  何かが重なっていたらエラー — 黙って捨てると「変換は成功したのに内容が
  欠落」が起きるため。上付き・下付きは基線が空白の列に書く。

## 手順3: 部分領域へ再帰する

- 親と同じ基線を引き継ぐ: デリミタのセグメント、√ の中身、打ち消しの
  中身、ブレースの引数。
- 基線を測り直す(手順1へ): 分数の分子分母、バンドの極限、矢印や
  ブレースのラベル、行列のセル、添え字の塊。

## 一意性を支える2つの仕掛け

**保護**: どこかの行で括弧対(格子の縁も含む)の内側にある列は、空白でも
「区切り」として扱わない。入れ子の行列の内部空白が親を分割しない理由。

**レンダラの分離義務**: 密着すると別のトークンに化ける組
(`──`+`──`・`══`+`══`、バンドと隣接要素(両側)、`─`/`═` と矢印の頭
`>` `<`(両向き)、英字ラン同士、打ち消しの
ぼろぼろの端。打ち消し直後に 2D 添え字が続くときは `⬚` アンカー)には、
正準出力が必ず空白1を入れる。
つまり「貪欲に読んで空白で止まる」だけで読みが一意になるよう、
書く側が距離を保つ。

## 手順4: 正規化 — 同じ絵は同じ AST に

同じ絵になる AST が複数あってはならないので、パース結果は必ず正規形に
落とす: 隣接する同種の添え字は合流(`x^a^b` ≡ `x^{ab}`)、空の
添え字・打ち消し・テキストは消す、極限なしバンドは基底が ∑ 系・lim 系の
単独原子のときだけ裸に展開(\op* 名前バンドは残す)、
入れ子の打ち消しは溶かす、デリミタ内の 1×1 行列はただの中身に(裸の
1×1 格子はフレームで区別できるので残る)、行頭行末の
整形スペーサは捨てる。エディタが作るどんな AST も、この正規形を経て
描かれ、描かれた絵はこの文書の読みで元に戻る — それが唯一の契約:

```
parse(render(normalize(x))) == normalize(strip_spacers(normalize(x)))
```
